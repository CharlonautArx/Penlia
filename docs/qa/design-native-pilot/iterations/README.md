# 试点视觉复查

## 原版现场记录

在 Chrome 中运行朋聊 Expo Web 离线版。画布为 390 × 844，语言为简体中文，系统浅色，上海时区。冻结样例时间为 2026-11-27 12:00，每次对照从同一批演示好友和活动起步。原版使用与基线提交 002ea55 相同的应用源码和素材，源自上一轮 f78d892 的 Web 导出。两提交之间的 src、assets 和 app.config.js 差异为空。

下图从左往右依次是聊天列表、小满单聊、动态、共同世界「晚风小院」和约局详情「周末到河边喝杯咖啡」。原版按照真实默认位置截取。这里只采用 Web 渲染图做布局复查，原生材料单独交付。[原尺寸拼图](original-web.jpg)

- 聊天列表的日期列清晰，搜索与会话列表缺少视觉分区。聊天视口顶部的历史消息会进入半透明标题栏下方。
- 朋友圈的首条照片在分段导航、权限和发布操作之后出现。封面、导航和发布连续占用较多纵向空间。
- 共同世界场景与格位需要同时可辨。多个浅色矩形的重量接近，格位按钮、宠物和纪念物难以分出前后。
- 约局的时间、地点、操作、私密选择、留言和空闲参考占用了两个以上的视觉层级，视觉强调却接近。首个实质候选只能露出一部分。

### 原版对照的逐像素核验

在同一机器上，使用相同的语言、时区、时间、滚动位置、演示数据与 390 × 844 浅色视口，将线上开发基线的 Web 导出和试用包的「原版对照」分别截取无损 PNG。单聊、共同世界及约局详情的 329,160 个像素全部相同。

| 页面 | 差异像素 | 最大单通道差（满值 255） | 全画面各通道平均绝对差 | 超出 5 色阶的像素 |
| --- | ---: | ---: | ---: | ---: |
| 聊天列表 | 6,972 | 6 | 0.01883 | 2（0.00061%） |
| 动态 | 2,464 | 7 | 0.00519 | 7（0.00213%） |

差异完全位于聊天列表四枚 48 × 48 头像及动态页一枚 62 × 62 头像内。两版这些源 JPG 的字节 SHA-256、实际图片引用、图片矩形、透明度和 object-fit 全部相同。同一已解码画面间隔 170 ms 再次截图，像素稳定。每个版本独立打开页面七次，候选版五枚头像出现的全部裁片像素哈希都能在旧版七次运行中精确复现。这说明所见色阶差在 Chromium 的跨次渲染中也存在。现有测量不能进一步定位到浏览器解码、缩放或合成子阶段。[逐页像素指标与独立重复记录](baseline-pixels.json)

### 选择器操作复查

在 360 × 800 深色运行中，首次打开自动进入方案选择；点返回落在原版聊天，在「我的」重新打开选择页。五种选择各跑过一次，以真实点按验证选中态，打开「好友动态」、后退并重新打开，再刷新后仍保持所选方案，无未处理 JS 异常。复查曾发现 Web 的单选项未向辅助技术暴露选中状态，补上 aria-checked 后重做。[实测选择器](picker-dark.png) · [状态检查](picker-state.json)

C 的第四轮还单独验证了向上滚动后搜索留在可操作的位置。单一输入框的顶边从页面初态的 y=87 移至屏内 y=13，在试点上一轮会滑出至 y=−193。滚动后实测搜索、清除与恢复列表。[滚动后画面](round4/C-search-scroll.jpg) · [布局采样](round4/C-search-scroll.json) · [同尺寸五版本首屏密度](density.json)

## 首轮 Android 原生实测与针对性修正

开发提交 0ac6c5c 的 x86_64 Release 安装在 API 35 模拟器。720 × 1600 的 Android 截屏显示，A 的收件首行确实像单项绿色选中，B 管理区视觉过密，C 的聊天标题与滚动内容争夺同一块空间。首条动态相片在 A、C 和 D 的出现位置也比后来几个版本低。后续修订对这些问题有直接对应的画面。[首轮原生聊天对照](round1/api35-chat.jpg) · [首轮原生动态对照](round1/api35-moments.jpg)

这一轮脚本完成 21 个带业务断言的标准画面。四个世界入口留下故障定位帧，四段约 33–34 秒的录屏仅包含部分收件与聊天操作。这次自动化作业报告失败。它用于发现和修正原生端问题，最终安装包的截图与交互通过情况另见对应构建记录。[首轮 Android Actions 记录](https://github.com/CharlonautArx/Penlia/actions/runs/46040876259)

原生运行还暴露出 Web 布局检查无法发现的两处差异。

- 在 A、C、D 单聊无壁纸的空白区域，实测屏幕像素均为纯白，浅色气泡之间缺少各自的背景材质。Android 优先解析 Viewport.android.tsx，而当时只有通用 Viewport.tsx 接受了试点底色属性。已在 Android 专用视口接入相同纸色，同时保留原有键盘补偿和个人壁纸叠放顺序。
- 英语模拟器下，约局的时间字段会在中文布局中显示英文月份及 AM/PM。试点展示采用中文日期、24 小时制，仍保留设备实际时区。正式页面的共享格式函数不受该调整影响。

在第三轮开发提交 ceb3fd5 上，再以 API 30、540 × 1080、夜间和系统字号 1.30 复核。原生截图中 A、B、C 动态顶部仍有明显的亮色渐变，D 左右窄边下的长标题会换行。这个时点的真实屏幕也解释了第四轮调整夜间无图封面的动机。[第三轮 Android 夜间动态实图](round3/api30-before-night-finish.jpg) · [对应 Android 运行记录](https://github.com/CharlonautArx/Penlia/actions/runs/46041720704)

第二轮提交 ee4c4e7 也在 Android API 35 独立构建并截屏。约局已将「直接提议时间」提前，不过未选时的灰色宽按钮仍然很突出。第三轮把选择动作贴到真实日期、降低未激活按钮重量，减少在两个不相邻位置间来回对照。[第二轮 Android 约局对照](round2/api35-gathering.jpg) · [对应 Android 运行记录](https://github.com/CharlonautArx/Penlia/actions/runs/46041237733)

## 最终 Android 夜间复查

复测沿用提交 37c33f9 构建的同一 x86_64 APK。Android 11 模拟器设为 540 × 1080、320 dp 宽、深色模式、系统字体 130%，全程离线。在原版与四套方案的 25 个页面中都取得原生画面。四套动态在无封面时的夜间标题清晰。四个约局版本均显示「2026年11月29日 14:00」，中文活动标题可完整换行。打开系统键盘后，四个单聊输入框内的 Hello、光标及发送控件都在键盘上方。C 的搜索在两次滚动后的中心位置都停在 y=101，仍可输入、筛选及清除。[原生验证记录](https://github.com/CharlonautArx/Penlia/actions/runs/46046972479)

在单聊无壁纸的测试数据上，以原生 PNG 的全宽、画面高度 13%–81% 为取样区，逐像素检查 Android 专用视口修复。夜间 A 的设计底色 #18211C 占该区域 37.32%，B 的 #11191A 占 33.17%，C 的 #16161A 占 37.96%，D 的 #221F1C 占 78.19%。其余像素包含实际头像、正文、气泡和联系人标题层。

同样的方法复核 Android 15 浅色聊天。A 的 #F8F6F0 占 44.76%，B 的 #FFFFFF 占 42.25%，C 的 #F1F2F6 占 46.47%，D 的 #F8F4EC 占 69.48%。四个试点的约局日期也以中文 24 小时制显示。
