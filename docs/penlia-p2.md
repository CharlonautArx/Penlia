## 主要代码及接口

- `server/p2/calendar.mjs` 管理 `/v1/p2/calendar`、`calendar-shares` 与 `availability/:id`。日程保持带时区时间戳，约局按候选时间后一小时校验已共享忙闲。
- `server/p2/spaces.mjs` 实现 `spaces` 和邀请、接受、拒绝、移除及退出。旅行的行程和转换在 `trips/:id`，收藏及地图在 `items`、`place-resonance`。
- `server/p2/memories.mjs` 实现 `memories`、`memory-sources`、`GET /v1/p2/memory-candidates`、`memory-settings`、`reminders` 和可选的 `POST /ops/p2/reminders/run`。应用内提醒使用服务端时钟，后台调用需独立令牌。
- `server/p2/capsules.mjs` 与 `status.mjs` 管理胶囊、音频及可过期的状态。照片与视频复用 P0 媒体传输，读取授权集中在 `server/p2/access.mjs`。音频另存，单条投稿最多 2 MB，每账号最多 32 MB。
- `src/app/life/`、`src/features/life/` 为 P2 界面；约局、日记和好友资料复用已有页面连接。Expo 音频与文件选择器用于本地音频，正式构建无需申请录音权限。

## 数据库与测试方法

新增 [006 P2 增量](../server/deploy/penlia-p2-dms.sql)，依次接在 003、004、005 后面。对应正式迁移 `server/migrations/006_life_p2.sql`，包含私密日程、成员项目、行程、授权收藏、地点、胶囊、生活状态、回忆和提醒。001 与 P0/P1 的既有增量文件保留。旧账号和已上传的媒体继续走原入口。

P2 收尾另有 [007 P2 收尾增量](../server/deploy/penlia-p2-followup-dms.sql)，对应 `server/migrations/007_p2_life_followup.sql` 与 DMS 生成开关 `--p2-followup`。等集中联调时通过独立迁移账号在 006 后执行。007 在事务内补充 `city` 字段，允许成对留空的地点坐标，并保留已有名称、地址、坐标和原表授权。006 及其 DMS 下载保持原样，日程和回忆候选复用既有表。

本地测试需使用回环 PostgreSQL 17 独立数据库，通过业务账号 `penlia_app` 运行，迁移账号与业务账号分离。P2 集成测试只接受 `penlia_p2_test`、55 开头的本地端口、临时迁移密码 `PENLIA_P0_TEST_ADMIN_PASSWORD`，并需要一段不超过 4 MB、30 秒的 `PENLIA_P0_VIDEO_FIXTURE`。测试用 `PENLIA_LIFE_JOB_TOKEN` 是合成令牌。正式配置留到最终联调。

```sh
npm run typecheck
CI=1 npx expo install --check
node --test tests/*.test.mjs server/deploy/dms-migration.test.mjs
node server/p2/p2.test.mjs
```
