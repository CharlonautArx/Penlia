## 代码与接口

- `server/p1/` 实现业务和授权，集中路由定义在 `server/p1/routes.mjs`。公开业务路由要求现有会话，前缀为 `/v1/p1`。
- `/wishes` 管理本人心愿和已授权共振，`/gatherings` 管理创建、意向、确认、封票及活动状态，`/events` 返回当前账号的通知记录。
- `/reports` 提交证据，`/boundary` 查看本人记录，`/reviews` 和 `/appeals` 要求工作人员角色。`POST /ops/p1/moderation/run` 使用单独的服务器间令牌，分批执行到期处置。
- `/groups/:id/call` 获取群通话状态或发起通话，`/calls/:id/*` 接听、续期、拒绝、退出及关闭。原生引擎契约在 `src/features/calls/group-provider.ts`。
- `/collections`、`/entries`、`/contributions` 管理共同记录、作者区分、版本、相册和发布权限。复用 `/v1/moments` 变更动态范围，复用 `/v1/moment-media` 上传和鉴权读取媒体。
- `src/app/social.tsx` 和约局、共同记录、审核路由复用原有界面组件。新入口位于玩乐、动态、我的和聊天，原有五栏顺序保留。

## 数据库增量

`server/migrations/004_social_p1.sql` 创建 P1 消息标签、心愿与授权、约局与候选、应用内事件、举报与审核、通话、共同记录及贡献版本表。既有 P0 表及已执行的原始迁移无需重建。新增关系使用外键、按调用范围设置索引，关键发布、发消息、处置与确认使用事务。共创授权可通过作者撤回单条贡献或发布者修改动态范围来撤销。P1 继续使用 P0 私密媒体限制，单文件 4 MB、单账号 32 MB。

DMS 可下载版本为 [penlia-p1-dms.sql](../server/deploy/penlia-p1-dms.sql)。它核对当前数据库与已应用的 P0 迁移，在一个事务内执行，业务角色只读审核员表。先在隔离库验证，把 004 排在 003 之后。使用 SQL Console 时以整段执行，检查最后的 `COMMIT` 和 `public.schema_migrations` 中的记录。

## 本地复测

```sh
npm run typecheck
CI=1 npx expo install --check
node --test tests/*.test.mjs server/deploy/dms-migration.test.mjs
node server/deploy/dms-migration.mjs --p1
```

集成测试使用独立、全新的回环 PostgreSQL 17 测试库。用迁移账号顺序执行 001、手机号 002、P0 003、P1 004 并单独授权运行角色 `penlia_app`。将 DMS 下载中的目标数据库名替换为测试库名称仅用于隔离测试。P1 测试需要测试库 `penlia_p1_test`、55 开头的五位端口、普通业务账号连接参数、临时迁移账号密码 `PENLIA_P0_TEST_ADMIN_PASSWORD`、临时密钥及 `PENLIA_P0_VIDEO_FIXTURE` 指向小于 4 MB 且不超过 30 秒的 MP4。隔离私聊回调测试还需临时 `EASEMOB_APP_KEY`、`PENLIA_IM_CALLBACK_SECRET`、`PENLIA_IM_CALLBACK_PATH_KEY`。运行 `node server/p1/p1.test.mjs`。P0 测试使用专用 `penlia_p0_test`，同样应用 004，再运行 `node server/p0/p0.test.mjs`。
