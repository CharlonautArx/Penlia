## 代码与接口

- `server/p1/` 实现业务和授权，集中路由定义在 `server/p1/routes.mjs`。公开业务路由要求现有会话，前缀为 `/v1/p1`。
- `/wishes` 管理本人心愿和已授权共振，`/gatherings` 管理创建、意向、确认、封票及活动状态，`/events` 返回当前账号的通知记录。
- `/reports` 提交证据，`/boundary` 查看本人记录，`/reviews` 和 `/appeals` 要求工作人员角色。`POST /ops/p1/moderation/run` 使用单独的服务器间令牌，分批执行到期处置。
- `/groups/:id/call` 获取群通话状态或发起通话，`/calls/:id/*` 接听、续期、拒绝、退出及关闭。原生引擎契约在 `src/features/calls/group-provider.ts`。
- `/collections`、`/entries`、`/contributions` 管理共同记录、作者区分、版本、相册和发布权限。复用 `/v1/moments` 变更动态范围，复用 `/v1/moment-media` 上传和鉴权读取媒体。
- `src/app/social.tsx` 和约局、共同记录、审核路由复用原有界面组件。新入口位于玩乐、动态、我的和聊天，原有五栏顺序保留。

## 数据库增量

`server/migrations/004_social_p1.sql` 创建 P1 消息标签、心愿与授权、约局与候选、应用内事件、举报与审核、通话、共同记录及贡献版本表。既有 P0 表及已执行的原始迁移无需重建。新增关系使用外键、按调用范围设置索引，关键发布、发消息、处置与确认使用事务。共创授权可通过作者撤回单条贡献或发布者修改动态范围来撤销。P1 继续使用 P0 私密媒体限制，单文件 4 MB、单账号 32 MB。

DMS 可下载版本为 [penlia-p1-dms.sql](../server/deploy/penlia-p1-dms.sql)。它核对当前数据库与已应用的 P0 迁移，在一个事务内执行，业务角色只读审核员表。先在隔离库验证，把 004 排在 003 之后，并接着应用 [005 收尾增量](../server/deploy/penlia-p1-followup-dms.sql)。使用 SQL Console 时以整段执行，检查最后的 `COMMIT` 和 `public.schema_migrations` 中的记录。

## P1 收尾验收

- **共创隐私。** 共创作者在「管理这条贡献的读者」分别授权现有成员和动态读者。动态范围扩大、关系组加入新成员、删除后重发动态都不会带入额外授权。为避免公开发起者的好友名单，作者可在符合动态范围的本人好友或共同成员中选人。撤权后，新的条目、相册和媒体请求立即受限。已有贡献按保守默认留给作者，待作者重新选人。此前已经下载到设备的内容无法从服务端追回。
- **普通举报。** 计划生效时间由数据库记录的人工确认时间加随机保护窗口计算。隔离测试把提交时间回拨 12 天，确认后仍有完整保护窗口，且生效时间前的任务不会执行。005 将旧的未生效普通工单按确认时间重排，重复执行不会二次改期，已执行处置不受影响。
- **小群约局。** 1–2 名受邀者时，服务端关闭匿名意向和封票统计，发起者直接提议，成员自行确认。其他约局仍需同一候选时间至少 3 票才能产生建议。“今晚”“明天”和周末快捷项按设备当地日期生成，过滤已经过去的时间。
- **证据。** 群聊附件由服务端从已提交且举报者可访问的消息提取，按工单加密归档并保存 SHA-256。审核员读取时进行身份、工单、完整性校验并记入审计。测试覆盖源文件删除、非法工单关联、图片及视频分段读取、密文篡改。老工单仅保留当时提交的元数据。
- **未来辅助审核。** 接口默认不可用。选中的内容必须来自用户主动提交且允许辅助审核的已核验证据，经审核员确认后使用区间遮盖及常见标识自动遮盖。输入只含角色类别、脱敏文本和附件类型。自动化只使用本地替身，供应商接入和裁决权独立。

复测结果为隔离 PostgreSQL 17 上 P0 8/8、P1 8/8、手机号 8/8，迁移、协议与日期单测 14/14。003、004、005 DMS 增量均重复执行通过。TypeScript 检查和正式模式 Android Hermes JS 包导出通过，最终 FC ZIP 本机 `/health` 通过。本次复测覆盖应用接口与构建，真机和云环境联调仍留到后续。
