# 「一起」的活动邀请与视觉边界

本轮从 `038bdc9` 延续开发。首页从受邀账号可读取的活动中选择近期活动，提供待本人处理的邀请，以及见面与出行、共同记录、日常生活三组入口。没有封面时使用本地绘制的低对比风景，照片只来自已有授权或本人选取。

## 局部设计

| 图集 | 在朋聊中的应用 |
| --- | --- |
| Apple A14、A17–A19 | 把封面、状态、标题合为同一构图。首页活动和详情延续相同封面，底部渐暗以保证中文标题的对比度。 |
| Apple A20–A21 | 活动照片和记录使用原日记与相册。成员操作置于独立浮层，个人回复不进入公开名单。 |
| Apple A24–A30、A40–A41 | 创建时先选填封面和活动说明。候选时间、携伴上限、私密决策等按需展开。 |
| Apple A23、A31–A38 | 对外分享先预览，邀请管理与参加确认分别操作。外发图片只排印用户核对过的标题。 |
| Partiful P16、P37–P39 | 参考创建后补邀、管理与再次发起的流程。 |

Together 导航栏在滚动内容上采样模糊，正文与日历使用稳定底色。按钮以可读文本、44 点以上触控区和轻微的边缘亮度区分操作层级。Android 31 以上使用 Expo Blur 的平台后端，较低版本或增强对比度时使用实底。iOS 读取减少透明度，Web 读取对比度与透明度媒体查询，浮层沿用已有减少动效偏好。Android 实际页面、滚动中的材质和高对比度对照见[原生验收记录](qa/together/README.md)。

## 作用域与共享文件

- `src/features/together/` 管理局部导航、材质、封面选择和邀请卡导出。只有「一起」或显式从这里进入的内部路由使用局部外观。共享页面的外部入口保留原组件。页面参数仅传递视觉作用域。
- `src/components/ui.tsx` 允许浮层调用方提供背景材质；现有浮层调用沿用默认背景。导航、全局主题、字体、聊天和动态组件没有本轮改动。
- `src/demo/life.ts`、`src/demo/together.ts`、`src/demo/state.tsx` 对预览账号保存本人选择，修复了写入后重启丢失活动状态的问题。单账号预览无法代表另一位成员确认。
- `server/http.mjs` 仅为创建和编辑活动封面设置请求体上限。P1 活动、贡献授权与 P2 日程、清单共用当前 API 和 PostgreSQL。迁移 `021_together_invitations.sql` 由现有迁移器按序发现。旧日记仍按原规则读取。
- 后端在读取活动、关联地点、清单、日记和媒体时分别校验访问权。更换当前页面或分享链接不授予成员资格。活动内日记使用独立的作者授权，撤回参加或被移除会结束其在这类日记的阅读资格并清理对应作品授权。

## 状态与边界

草稿按本机账号区分，发邀请携带稳定请求 ID。时间与地点可待定；填写结束时间后才可按完整时段判断冲突。旧活动缺少结束时间时不推断一小时。个人意向和正式确认独立，邀请选择被封存后，符合隐私阈值才显示共同建议。重新发起以新的邀请和名单开始。

改期清除旧确认并移除关联的私人日程与提醒。候补收到名额后仍需本人接受。共同筹备者接受后仅能补充候选时间。私人备注仅对本人和发起人可读。活动前提醒随「一起」页面读取，尊重既有安静设置。导出的标题图片不包含成员、地址或活动照片。日程双向同步、系统推送、免安装来宾网页及商业地图天气服务均留待外部接入。

## 验证入口

`npm run typecheck` 检查客户端类型；`node --test --test-isolation=none tests/*.test.mjs server/security.test.mjs` 运行基础回归。`server/p1/together.test.mjs` 使用专用回环数据库、多个测试账号和真实 HTTP 请求验证并发确认、候补、幂等、改期、资料修改、来源权限、现场日记与撤权。该测试拒绝非隔离数据库配置。原有 P1、P2、P3 集成测试仍需一并运行。

预览使用 `EXPO_PUBLIC_PENLIA_UI_DEMO=1`，进入后打开「玩乐 → 一起」。预览版的系统相册、导出及系统分享往返有模拟器实录。ARM64 实体设备与跨设备已登录账号仍需复核。
