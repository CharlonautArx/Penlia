# 朋聊动态、空间与状态验收

代码基线为上一版玻璃材质和玩乐改造的 `dd80ef2`，已核对 Android 启动修复、字体、品牌材质和 P0–P3 均在该历史中。本轮代码提交为 `d90d197`。

## 界面与兼容路线

| 路径 | 行为 |
| --- | --- |
| 底栏「动态」 | 显示本人的空间封面、头像和「动态／日志／相册」。好友动态按原始发布时间倒序，置顶不影响该时间流。发布入口继续使用原服务端编辑器及其可见范围。 |
| 动态首页 → 本人头像 | 进入「我的动态」。统计值来自当前用户的权威动态总数和两类本机空间记录；时间线按置顶、原始发布时间、记录 ID 倒序排列。 |
| 动态首页 → 好友头像 | 进入该作者的可见动态，查询始终通过原有访问控制。 |
| 动态首页 → 日志／相册 | 打开既有空间内容。可在原路径浏览、编辑和创建日志，依照既有能力管理相册和照片。 |
| 底栏「我的」 → 资料卡片 | 进入「个人资料」，原编辑按钮保持独立。地区、近况使用原空间中本机补充资料。 |
| 底栏「我的」 → 状态 | 只编辑文字、图片和受众，可修改或清除；本次保存的状态持续到用户主动替换或清除。 |

旧 `/moments?mine=1` 和 `/moments?author=…` 转到相应个人时间线，`/moments?local=1` 和旧 `/space/[id]` 仍能访问旧本机内容。原空间文档 `penlia.space.v1.<uid>` 使用原结构保存照片、封面、日志、相册和旧动态，旧「关于」和访客、留言板的数据没有因导航调整被删除。动态留言仍可从每条动态的留言面板进入。

## 数据与访问控制

- 正式模式的权威动态和参与记录分别保存在 `private_moments`、`moment_likes`、`moment_comments`。动态列表、详情、图片、点赞和留言使用原有内容、关系、拉黑及共创授权校验。已取消授权的留言作者不再出现在当前读者可见的互动汇总中。
- 转发使用当前用户原有聊天发送流程，只传送受保护的原动态链接。没有权限的人打开链接时不会收到正文或图片。当前未部署的通信环境不提供跨手机真实转发测试。
- 旧设备动态通过自己时间线的「本机旧动态」继续查看和编辑。保留原记录 ID、权限和媒体引用，未自动上传，主时间线和计数只使用权威动态接口。本机封面、日志和相册沿用原存储，应用升级需保留同包名且同签名的安装与应用数据。将来如需设备历史上云，需要逐项确认受众并建立旧 ID 到服务端 ID 的幂等映射。
- 离线演示通过同一组客户端接口调用本机实现，使用演示身份和已有持久化存储。演示点赞、留言、转发和新动态只在本机保存。
- 迁移 `009_unified_moments.sql` 新增个人置顶和互动表，允许 `p2_status.expires_at` 为空。旧记录原时间保持不变，旧过期内容不会恢复。新版查询 `?lifetime=1` 返回实际的空值。仍只识别日期的旧客户端收到兼容日期和 `persistent: true`，数据库里不存该日期；旧客户端设置临时期限时，服务端保护已有长期状态并提示升级。旧客户端仍可明确清除。
- 部署次序为备份、在隔离或预发验证 009、授予既有运行角色所需的最小权限、部署 API，再发布正式客户端。DMS 脚本为 `server/deploy/penlia-unified-moments-dms.sql`。本次测试没有连接生产数据库或启用通信服务。

实际安装后连续 5 次冷启通过，登录演示、五栏、日志、相册、资料页、状态设置与清除、重启后的置顶和状态均已验证。五次 ADB 启动记录为 2,943、1,957、2,235、2,786 和 2,107 毫秒，期间目标应用的致命崩溃数为 0。初两轮脚本因点到同名文本和输入末尾空格而中断，已更正定位规则并使用同一 Release 包完成全程。 [GitHub Actions 日志和原始截图](https://github.com/CharlonautArx/Penlia/actions/runs/44920813277)

模拟器用 x86_64，与 ARM64 包的 1,379 项 Hermes Bundle、DEX、清单和资源逐项一致。ARM64 的 27 个原生库均与上一版字节一致，模拟器沿用同一基线的对应 x86_64 原生库。ARM64 真机和鸿蒙卓易通仍待实装，正式跨设备动态、转发和媒体撤权须在获批的联调环境验收。
