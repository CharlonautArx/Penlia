# 手机号认证与费用保护

本分支包含服务端认证接口和独立增量 SQL。FC 入口默认不注入供应商，手机号接口返回 503，朋聊号密码登录继续可用。开发测试使用本机 PostgreSQL、临时凭证、签名票据模拟器和短信记录器。

## 请求与旧账号兼容

1. **签发挑战**　POST /v1/phone/challenge 校验中国大陆手机号、安装标识、基础风险及可用预算。服务端签发 120 秒挑战，绑定手机号摘要、可信 IP 范围、安装标识和业务用途。旧账号绑定额外绑定已登录用户 ID，并要求重新验证原密码。
2. **核验与发送**　POST /v1/phone/send 确认上下文，原子消费挑战并登记输入票据及验证码核验额度。可信供应商通过服务端校验后，再在独立事务登记稳定票据 ID、重查有效期和风险、预留最坏情况短信费用并作废旧验证码。只有事务确认后才允许提交一条短信。
3. **验证与开户**　POST /v1/phone/verify 将验证码消费和结果记录在同一事务。已绑定用户恢复原 UID 的会话。新号获得 10 分钟的一次性开户凭证，POST /v1/phone/onboard 原子写入用户、唯一手机号映射和会话。朋聊号沿用 3–24 位小写字母、数字或下划线。未验证号码时，返回状态不暴露是否注册。
4. **绑定旧账号**　已登录旧用户走 /v1/phone/bind/challenge、bind/send 和 bind/verify，新映射引用原 UID，环信身份与好友表原样保留。绑定冲突要求使用原账号，系统不自动合并。手机号换绑需另设计旧号码和账户恢复验证。正式头像需要独立媒体存储与授权。

OTP 由 Node.js 加密随机数生成，五分钟有效，错误五次失效。应用数据库保存手机号、上下文、票据和 OTP 的 HMAC 校验数据。供应商调用期间使用手机号和 OTP，应用不将明文写入数据库或日志。公开好友搜索仍按朋聊号。手机号新用户在旧密码字段保存无人知晓的随机占位值，以兼容现有密码格式和空值约束。

正式滑块适配器须证明手动验证通过，向服务内返回 Penlia 挑战 ID 和供应商稳定票据 ID，并校验绑定、场景、有效期、验证方式和风险等级。公开文档中的示例响应不足以证明挑战能安全绑定到本次请求。正式接入前要用获批的渠道验证，不能把客户端输入、拖动距离或容灾票据作为证明。无障碍渠道也须获得服务端核验。

## 风控、额度与审计

| 范围 | 试运行默认 |
| --- | --- |
| 单手机号 | 90 秒冷却、滚动 1 小时 3 次、24 小时 5 次 |
| 可信 IPv4 或 IPv6 /64 | 每小时 15 次，最多 10 个不同号码 |
| 安装标识 | 每小时 6 次，最多 3 个不同号码 |
| 平台突增 | 滚动 10 分钟到 10 次即暂停新发送 |
| 付费前的挑战与核验 | 自然日最多签发 150 个挑战，最多 100 次服务端核验；挑战同时按手机号、IP 和安装标识限流 |
| 短信 | 上海自然日最多 60 次，整数微元预算最多 ¥3 |
| 月度预警 | 上海自然月到 ¥30 预留金额后写入一次预警 |

数据库集中控制开关、次数、金额和单次预留成本。实例配置只能收紧额度或加大单次费用预留。PostgreSQL 事务跨实例共享预算。数据库故障时关闭发送。供应商拒绝、超时或未对账同样占额度，系统不自动重试或退额度。若后续账单高于预留，按两者中较高的金额计算后续额度。关闭开关时，已获授权的请求可能仍在途。

系统分别存储受理、送达、认证成功及已知计费。受诊断令牌保护的 GET /ops/phone-usage 返回聚合统计、未对账数量和月度预警状态。回执写入只能由可信服务端逻辑调用。实际回执验签、账单抓取和月度通知推送待正式接入。

目前只取 TCP 对端 IP，忽略请求方任意填写的转发头。FC 入口启用前须验证网关可信边界及真实 IP 来源。安装标识是辅助风控信号，轮换或代理行为主要由不同号码数、突增和全局预算兜底。代理信誉库未接入。建议单独评估共享网络误伤。拟保留失效挑战和短期风控摘要最多 7 天，短信费用审计最多 90 天，手机号 HMAC 映射随账号存续。清理任务和密钥轮换方案在生产接入前配置。替换 HMAC 密钥需双读或重绑，直接替换会使旧映射无法识别。

## 正式部署与验证

1. 批准供应商、资质、短信模板、验证码场景和预算，再实施真实适配器。用少量白名单真机核对人工滑动、票据上下文及一次性、无障碍替代、实际收信和账单数据。
2. 备份后复核独立增量 SQL 和最小授权。原 DMS 基础脚本保留，增量未加入既有部署。此轮只在本机试验重复执行，云端数据库需单独授权。
3. 通过服务器密钥管理部署，明确 FC 入口可信源 IP、密钥限制、告警和审计清理。管理员在持有手机号模块事务锁的管理事务中配置共享硬上限及开关，应用账号没有修改开关的权限。白名单通过后再扩大流量。
4. 旧用户先在原账号登录后绑定。正式环境验证现有账号、好友、聊天 UID、会话恢复及失去手机号后的恢复流程。单独验证运营商回执和月度通知链。

本地测试使用独立的 penlia_phone_test 和临时 PostgreSQL 用户。先应用基础 SQL、P0 增量 `server/migrations/003_privacy_p0.sql` 和两者的业务授权，测试数据库名替换基础授权脚本中的 penlia_dev。设置 PGHOST 为 127.0.0.1、PGDATABASE 为 penlia_phone_test、PGUSER 为 penlia_app、PG_TLS 为 disable，并注入临时 PGPASSWORD 和 PENLIA_PHONE_TEST_ADMIN_PASSWORD。执行 node server/phone/phone.test.mjs。测试仅允许指定的回环测试数据库，会清理手机号测试表。模拟票据和验证码不写入日志。
